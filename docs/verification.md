## 2026-10-04 · 所有人声仅使用 MiniMax 录音

彻底删除 Narrator 的浏览器语音合成分支、合成语音参数与生产代码中的测试兜底。示范、慢速跟读、鼓励、中文引导和结果只通过本地 MP3 播放。文件缺失、播放被浏览器阻止或加载失败时返回失败并保持静音；提示可重新播放录音。语音索引临时加载失败后可重新请求，暂停仍取消正在播放和异步等待的台词。

原来按文字长度设置的播放超时会截断部分第四至第六关的长反馈，再切换成浏览器合成音。现在根据音频实际时长和播放位置设置等待时间，以实际结束事件完成播音；较长录音不再因文字较短被中断。

生产构建 `npm run build` 通过。src 与生产 JS 中 `speechSynthesis`、`SpeechSynthesisUtterance` 和旧合成分支引用为 0，src 中测试注入标记也为 0。测试改为模拟录音播放器，禁止访问浏览器语音合成 API；真实 MP3 播放另行验证。

录音专项 `tests/recordings.spec.ts` 在静态构建上 **6 项通过（43.7 秒）**：

1. 索引中缺少台词时保持静音，出现重试提示。
2. MP3 返回 404 时保持静音，出现重试提示。
3. 浏览器拒绝播放时保持静音，出现重试提示。
4. 索引首次返回 503 后，重试重新请求并完整播放已有录音。
5. 等待索引时暂停，加载完成后不播放过期台词，恢复后只播放一次。
6. 用第六章约 9 秒的真实反馈录音验证播放等待，完整结束且未被暂停截断。

六项均断言没有访问浏览器语音合成。全部关卡所需台词、慢速跟读和共享鼓励存在；进一步解码全部已索引的 **375 个录音文件**，全部有内容、有声音信号、可解码，最长 9.36 秒。报告：docs/voice-asset-checks.json。无需重新生成语音或调用云端。
